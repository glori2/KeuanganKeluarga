# 🤖 TELEGRAM BOT SECURITY & INTEGRATION GUIDE

**Application:** KeuanganKeluarga  
**Architecture:** Next.js 16 Webhook + Supabase PostgreSQL + Telegram Bot API  
**Status:** Production-Ready Hardened (Phase 5)

---

## 1. Overview & Threat Model Remediation

Prior to Phase 5, the Telegram bot implementation exhibited serious security flaws including insecure auto-linking on /start, missing webhook secret authentication, non-idempotent updates, and non-atomic mutations.

In Phase 5, the entire Telegram interface was rebuilt around strict security principles:
- **Zero Insecure Auto-Linking:** Unknown Telegram users can never hijack member records or join arbitrary families.
- **Cryptographic OTP Linking:** High-entropy 8-character OTP codes generated by authenticated web users with single-use enforcement and 10-minute TTL.
- **Timing-Safe Webhook Secret Verification:** Validates X-Telegram-Bot-Api-Secret-Token header using crypto.timingSafeEqual against constant-time attacks.
- **Database-Backed Idempotency:** Tracks incoming update_id in PostgreSQL table 	elegram_updates to prevent duplicate transaction entries from network retries.
- **Row-Locked Atomic Financial Mutations:** All bot commands (/catat, /masuk) use sql.begin with FOR UPDATE row locks, ensuring consistency and exact balance reconciliation.

## 3. Webhook Setup & Configuration

### Environment Variables
Configure the following in .env.local or Vercel Environment Variables:
`env
TELEGRAM_BOT_TOKEN=<YOUR_TELEGRAM_BOT_TOKEN>
TELEGRAM_WEBHOOK_SECRET=<YOUR_SECURE_RANDOM_SECRET_STRING>
`

### Webhook Registration Command
Register the webhook endpoint with Telegram API using curl:
`ash
curl -X POST https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/setWebhook \
     -H Content-Type: application/json \
     -d '{
       url: https://your-domain.vercel.app/api/webhook,
       secret_token: <YOUR_SECURE_RANDOM_SECRET_STRING>,
       allowed_updates: [message, callback_query]
     }'
`

## 5. Security Test Coverage

The Telegram security layer is tested by 	ests/telegram_security_test.js covering 17 distinct automated assertions:
1. Valid webhook secret token accepted (HTTP 200).
2. Invalid webhook secret token rejected (HTTP 401).
3. Missing webhook secret token rejected (HTTP 401).
4. Length-mismatched token rejected safely without timing leaks.
5. High-entropy 8-character OTP generation.
6. OTP storage with used_at = NULL and correct foreign keys.
7. Successful OTP link binding to nggota.telegram_id.
8. 	elegram_chat_id capture for direct notifications.
9. Replay protection (immediate rejection on reused code).
10. Expiration enforcement (rejection on expires_at < NOW()).
11. Non-existent/tampered code rejection.
12. Zero auto-linking for unknown users on /start.
13. Webhook idempotency (first delivery accepted).
14. Webhook idempotency (duplicate delivery ignored).
15. Strict tenant context resolution from Telegram ID.
16. Family A balance atomic mutation.
17. Tenant isolation (Family B balance completely unaffected).
